Released on 19 November. It follows
[1.1.0](/changelog/november-2026/1.1.0). Download it from
[peridio.com/downloads](https://peridio.com/downloads) or the
[GitHub release](https://github.com/avocado-linux/avocado-cli/releases/tag/1.2.0).

## Upgrading from 1.1.0

- **`ext build` may compile less, or more.** A compile section is now skipped
  when nothing it reads has changed, but only when every extension that names
  it lists `package_files`. An extension package with both `compile` and
  `install` is always rebuilt. See
  [Compile sections](/developer-reference/lockfiles-and-build-stamps#compile-sections).
- **Build volumes are checked against the daemon.** If the volume a project
  recorded is missing from the current Docker daemon, commands stop instead of
  starting over in an empty volume. This happens after `avocado vm reset`, a
  Docker data purge, or a switch to another daemon. Run `avocado clean` to
  start the project over.
- **`sdk dnf`, `ext dnf` and `runtime dnf` pass each argument as given.** An
  argument with `$VAR`, a glob or `&&` now reaches dnf literally instead of
  being expanded by the container shell.
- **`deploy -d` checks the device string.** The user may hold only letters,
  digits, `.`, `_` and `-`. The host may hold those plus the `:` and `%` of an
  IPv6 address, or be a bracketed IPv6 address such as `[::1]:2222`. Neither
  may start with `-`.

## New

- **[Rubicon](/developer-reference/rubicon) boards.** `avocado rubicon` lists
  the boards you can reach on your own VM and on your org's VM hubs, runs a
  project's run profiles (`rubicon.run.<name>`) on a board, opens or watches
  the board's serial console, claims boards for your Connect org, updates
  their firmware, and shows and cancels hub jobs. `avocado vm rubicon`,
  `vm connect` and `vm service` set up a VM as a hub.
- **Provision through a Rubicon, and provisionable bundles.**
  `avocado provision --rubicon` provisions a board on a hub, from your desk or
  from CI, with `--interactive` for a person at the board's console.
  `--pack` writes a provisionable bundle and `--bundle` replays one on a
  machine with no build tree. `connect upload --provisionable`,
  `connect bundle upload` and `connect provision` do the same through
  Connect. A provision profile names the run profiles a hub runs around it
  with `rubicon: { before, after }`.
- **The `docker` client no longer has to be installed.** The CLI talks to the
  Docker daemon itself over the Engine API. `DOCKER_HOST` and the current
  docker context work as before. Set `AVOCADO_DOCKER_CLI=1` to use the
  `docker` command everywhere. See
  [Installation](/developer-reference/avocado-cli/installation#requirements).
- **`avocado vm` on Windows**, as a preview. The VM boots under QEMU with
  WHPX, and `provision` runs through it. The workspace share uses SMB and
  needs a one-time elevated setup.
- **`--offline` and `AVOCADO_OFFLINE`.** The CLI skips its snapshot, pin and
  feed lookups and uses the locked pin. dnf inside the SDK container still
  needs the network. See
  [Working offline](/developer-reference/package-feeds#working-offline).
- **`avocado feed index <dir>`** writes the repository metadata for a
  directory of RPMs with the host's `createrepo_c`, so the directory works as
  a `path:` feed.
- **Feed checks before downloading.** `install`, `sdk install`, `fetch` and
  the other install commands check each feed first. An unreachable feed, or
  one with no metadata, fails at once with an error naming it.
- **`provision --dry-run`** runs every check of a profile and writes nothing,
  for a profile whose manifest declares `config.dry_run: true`. Provision
  scripts also get `AVOCADO_PROVISION_FORCE`, and on a Linux host running
  Docker directly, `AVOCADO_PROVISION_HOST_MOUNTS`. See
  [Provisioning](/developer-reference/provisioning#what-a-provision-script-receives).
- **A `container:` block** on `sdk` and on each provision profile sets
  `privileged`, `network_mode`, `volumes`, `devices`, `extra_hosts`,
  `cap_add` and `environment` by name. See
  [Container settings](/developer-reference/avocado-cli/configuration#container-settings).
- **`rewrite_loopback` on a feed** under `repos:`. A feed served from
  `localhost` is mapped to an address the build container can reach, unless
  the container shares the host's network. See
  [Feeds served from localhost](/developer-reference/package-feeds#feeds-served-from-localhost).
- **`provides`, `epoch` and scriptlets** (`pre_install`, `post_install`,
  `pre_uninstall`, `post_uninstall`) in `sdk.compile.<section>.package`. See
  [Cross-compilation](/developer-reference/cross-compilation#provides-epoch-and-scriptlets).
- **`avocado init --minimal`** writes a project without the default dev and
  board support extensions, for a feed that does not carry them.
- **`ext clean --skip-compile`** cleans an extension and leaves its compile
  sections as they are.
- **Pins remember their feed.** A snapshot pin records the feed URL it came
  from, so pointing the project at another feed warns instead of reusing a
  snapshot that feed never issued. A pinned rebuild says when a newer snapshot
  exists.
- **`pin ignored` notice.** With `AVOCADO_RELEASEVER` set in a project that
  has a locked pin, the CLI says once per run that the override wins.

## Changed

- **`avocado install -r <runtime>` scopes its SDK step to that runtime** and
  the extensions it depends on. Before, it installed the SDK packages of
  every runtime of the target. A runtime not defined for the target is an
  error.
- **`provision --env KEY=VALUE` also fills `{{ env.KEY }}`** in
  `avocado.yaml`, ahead of your shell's environment.
- **`avocado connect` commands honor `AVOCADO_CONNECT_TOKEN` and
  `AVOCADO_CONNECT_URL`.** A set token replaces the saved profiles and is
  never written to disk.
- **An empty extension `version` fails** like a missing one, and says when a
  templated version is empty because its variable is unset.
- **`sdk install` cleans the target sysroot when the kernel pin changes**, so
  out-of-tree modules don't compile against the old kernel's headers.
- **New projects require CLI 1.0.0 or later** (`cli_requirement: '>=1.0.0'`).
- **Named rootfs entries and `target-<name>:` overrides apply at install and
  at the image step.** Before, a named entry's `overlay`, `post_install` and
  `image` were ignored, and a `target-<name>:` block changed only the image.
  See [Rootfs configuration](/developer-reference/avocado-cli/configuration#rootfs-configuration).

## Fixes

- **`connect auth login` works over ssh.** Paste the URL from the browser's
  address bar at the CLI's prompt when the browser can't reach the machine
  the CLI runs on.
- **A bare `vm start` boots the source last chosen.**
- **The VM's docker tunnel comes back** whenever the VM is awake, not only
  after a Docker connection woke it.
- **The rootfs keeps package-owned directories under `/boot`**, such as
  mount points. Before, their mounts failed on every boot.
- **A failed run's summary no longer calls skipped steps "up to date".**
- **HTTP 429 from a feed is reported as rate limiting**, with how long to
  wait, instead of "No more mirrors to try".
- **`load --force` removes the volume it replaces.**
- **A failed `ext fetch` of a short commit hash** suggests the full hash, a
  branch or a tag.
- **A quoted `container.environment` value keeps its edge spaces.**
- **Runtime builds no longer print `ERROR: zoned: unable to stat`.**

## Security

- **`deploy -d` no longer runs shell syntax** from the device string inside
  the SDK container.
- **`credentials.json` is readable by your user only** (`0600` in a `0700`
  directory). A looser file is tightened on the next save.
- **`avocado clean` removes `.avocado/overlay-staging/`**, which can hold
  rendered secrets.
- **`sdk package` rejects a `requires` entry holding a newline.**
- **RustSec updates:** `quinn-udp` 0.5.16, `anyhow` 1.0.104, `rustix` 1.1.6
  and `tokio` 1.54.1.
