Released on 11 November. It follows
[1.0.0](/changelog/october-2026/1.0.0). Download it from
[peridio.com/downloads](https://peridio.com/downloads) or the
[GitHub release](https://github.com/avocado-linux/avocado-cli/releases/tag/1.1.0).

## Upgrading from 1.0.0

- **Most extensions rebuild once.** The build hash now includes the sysroot
  tree. An extension with a `compile` or `install` package and no
  `package_files` rebuilds on every build. A switch to a different runtime also
  rebuilds the extension.

## New

- **Per-target distro overrides.** A `target-<name>:` block inside `distro:`
  now applies to that target. Before, the CLI ignored it. One board can stay on
  a different release or channel:

  ```yaml
  distro:
    release: 2026
    target-raspberrypi0-2w:
      release: 2024
  ```

  A key that the block sets replaces the base key, also in
  `{{ config.distro.* }}` and in the SDK image tag. `avocado update --target`
  gets the snapshot from the feed of that target.

- **`runtimes.<name>.var.initial_os_rollback`** (default `true`). Set it to
  `false` to leave the OS bundle out of the provisioned var image. The var
  image is then smaller, but the device cannot roll back to the provisioned
  OS. The signed manifest and OTA updates do not change.

## Changed

- **`enable_services` on an extension without `confext` is a warning**, not an
  `[ERROR]`. It was never fatal.

## Fixes

- **`enable_services` accepts a template instance**, such as
  `wpa_supplicant@wlan0.service`, when the extension ships the template. If the
  template comes from the rootfs, the build still fails, and the error tells
  you to put the link in the overlay.
- **`ext install` and then `ext build` works in a project with one runtime.**
  `ext install` now takes `-r/--runtime`. Without it, the command uses the only
  runtime or the default runtime.
- **A new extension version leaves only one release file.** Before, the old
  `extension-release` files stayed in the image, and the device ran the
  `AVOCADO_ON_MERGE` hook of each old version.
- **A re-provision no longer reuses a larger, stale var image.**
- **`--sdk-arch` gets to `ext image` and the provision version query.** On an
  arm64 host with an x86_64 SDK, the build failed with
  `mkfs.erofs: command not found`.
- **`avocado install` keeps extension sysroots when a runtime reinstalls
  clean.** Before, `build` then stopped with "has no package database".
- **The SDK install no longer moves the container's own tools, such as
  `uname` and `mv`, out of `/usr/bin`.** This caused "command not found" in
  later steps.
- **`ext build` no longer skips a stale sysroot** after an edit to a source
  that an `install` script copies, or after a build of a different runtime.
- **`connect runtimes list` shows draft runtimes.**
- **`avocado-ext-cli` builds again.**
- **Security.** `config validate` no longer shows environment variable values
  in error paths or messages. Before, a `{{ env.X }}` key showed its value in
  the error path, so a tool that showed the result also showed the token.

## Release files

- **`SHA256SUMS` verifies every archive.** `sha256sum -c` failed for the
  Windows and Linux (gnu) archives.
- **The Homebrew formula is current again.** Each release now opens the tap
  update as a pull request.
